# Diamond Mountain 移行分析

調査日: 2026-09-30

## 1. 現在のファイル構成

現在の実行アプリは、Vue/Viteを使わない静的HTML/JavaScript構成である。

- `index.html`: UI、Leaflet CDN、各JavaScriptの読み込み順を定義
- `css/style.css`: 地図、操作パネル、ポップアップのスタイル
- `js/constants.js`: 天文、検索、地図、標高、UIの定数
- `js/utils.js`: 日付、数値、メッセージ、地図表示補助
- `js/config.js`: 山データと山選択メニュー
- `js/astronomy.js`: 太陽位置、日の出・日の入り、方位・仰角
- `js/elevation.js`: 国土地理院APIによる標高取得
- `js/visibility-boundaries.js`: 太陽方位の可視範囲と境界線
- `js/sun-direction.js`: 日の出・日の入り方向線
- `js/periods.js`: 複数年検索、結果表示、CSV出力
- `js/main.js`: Leaflet初期化、状態、イベント、クリック時検索

`_ignore/`には過去版や作業メモが保存されているが、現行実行コードではない。

現時点で、`package.json`、Vite設定、Vueソース、テスト設定は存在しない。

## 2. 太陽の計算処理

主な処理は`js/astronomy.js`にある。

- `toJulianDayUTC()`でUTC日時をユリウス日に変換する
- `sunPositionJD()`で太陽黄経と赤緯を近似計算する
- `sunAltAzLocal()`で観測地点の太陽高度と方位を計算する
- `sunRiseSet()`で日の出・日の入り時刻と方位を計算する
- `bearingAndApparentElevation()`で観測地点から山への方位角、仰角、距離を計算する
- `angleDiff()`で方位角の最小差を計算する

`sunRiseSet()`は均時差、太陽赤緯、天頂角`90.8333°`を使う。一方、太陽の時刻別高度・方位は別の近似式で計算されている。

検索では、太陽の方位・高度と山の方位・仰角を比較し、指定された方位許容差・仰角許容差以内か判定する。

タイムゾーンは`CONSTANTS.JST_OFFSET = 9`として固定されている。移行時には、日付、時刻、タイムゾーン、地平線付近の補正を既存挙動と比較しながら扱う必要がある。

## 3. Leafletの処理

Leafletは`js/main.js`で初期化される。

- `L.map('map')`で地図を生成する
- OpenStreetMapタイルを追加する
- `window.visLayer`、`window.sampleLayer`をレイヤーとして保持する
- `window.mtMarker`で山マーカーを保持する
- `window.lastClickedLocation`で最後の観測地点を保持する
- 地図クリック時に観測地点処理または山登録処理を実行する

描画処理は次のファイルに分散している。

- `js/sun-direction.js`: 日の出・日の入り方向線と`window.sunDirectionLines`
- `js/visibility-boundaries.js`: 可視範囲境界線と`window.visibilityBoundaries`
- `js/main.js`: レイヤー消去、山マーカー、ポップアップ

Leafletインスタンス、レイヤー、マーカーが`window`グローバルに保存されている。Vue移行時は、地図を所有するコンポーネントがライフサイクル内で生成・更新・破棄する構造にする必要がある。

## 4. 山の検索処理

山データは`js/config.js`の`mountains`オブジェクトにある。現在の登録山は鳥海山、月山、富士山、八ヶ岳である。

### 山の選択・登録

既存の山を選択すると地図を移動し、山マーカーを表示する。

山が未選択の状態で地図をクリックすると、次の処理を行う。

1. 標高APIを呼び出す
2. `prompt()`で山名を入力する
3. `mountains`へ実行時追加する
4. セレクトボックスへ追加する
5. 山マーカーを表示する

追加した山は永続化されず、ページ再読み込みで消える。

### クリック地点での詳細検索

`js/main.js`の`findDetailedAlignment()`が担当する。

- 朝と夕方の時間帯を検索する
- クリック時は基本的に1分刻みで計算する
- 太陽高度が最低高度以上の場合だけ比較する
- 方位差と仰角差が許容範囲内か判定する
- 最初、最後、最良の一致を返す

現在は検索対象が太陽に固定されている。

### 複数年検索

`js/periods.js`の`searchDiamondPeriods()`が担当する。

- 5分刻みで粗く検索する
- 候補周辺を1分刻みで精密検索する
- 年単位で結果を整理する
- 同じ日の候補を最良のものに絞る
- 該当がない年は最も近い時刻を返す
- 別ウィンドウに結果表を表示する
- CSVを出力する

クリック時検索と期間検索には、太陽位置と誤差判定の類似処理が重複している。将来は天体アダプターを受け取る共通検索ドメインへ整理する候補である。

## 5. 標高API

標高取得は`js/elevation.js`で実装されている。

利用APIは国土地理院の標高APIである。

```text
https://cyberjapandata2.gsi.go.jp/general/dem/scripts/getelevation.php
```

処理の特徴は次のとおり。

- `fetch()`を使用する
- `AbortController`で5秒のタイムアウトを設定する
- 標高値とデータソースを返す
- HTTPエラーや標高未取得を捕捉する
- 取得失敗時は標高`2m`を仮定して処理を継続する

取得失敗を計算停止として扱わず、デフォルト値で継続する仕様である。Vue移行時には、取得中、成功、失敗、代替値使用中、エラー内容を明示的な状態として管理する方がよい。

## 6. 現在のビルド・公開方法

現在はビルド工程がない。

- `package.json`なし
- `npm`スクリプトなし
- Vite設定なし
- GitHub Actionsのビルド設定なし
- LeafletのCSS/JSをCDNから直接読み込む
- `index.html`を起点にブラウザで直接実行する

`index.html`では、Leaflet、定数、ユーティリティ、山データ、天文計算、標高、可視範囲、方向線、期間検索、メイン処理の順序に依存している。この順序が、現在のグローバル関数・グローバル定数の実行条件である。

Gitの`origin`は`ja7jnv/ja7jnv.github.io`を指し、作業ブランチは`develop`である。直近コミットの「Vue化を開始」は、Vue実装ではなく移行方針ファイルの追加であった。

したがって、現状はGitHub Pagesでリポジトリ内の静的ファイルを直接配信する運用と考えられる。ただし、リポジトリ内にPagesのビルド設定自体は確認できなかった。

## 7. Vue移行で最初に手を付けるべき箇所

最初に対象にすべきなのは、天文計算式の変更ではなく、アプリケーションの起動と状態管理である。

### 推奨する初期段階

1. 現行版の太陽機能を基準動作として記録する
   - 山選択
   - 地図クリック
   - 標高取得
   - 方位・仰角表示
   - 可視範囲表示
   - 期間検索
   - クリア・再表示

2. 最小限のVue/Vite基盤を追加する
   - `package.json`
   - Vite設定
   - Vueエントリーポイント
   - `App.vue`

3. 既存UIを一度に作り替えず、まず状態をVueへ移す
   - 観測地点
   - 対象山
   - 開始日
   - 探索年数
   - 許容誤差
   - 標高取得状態
   - メッセージ
   - 計算状態

4. 天文計算は当面、既存関数をそのまま移植して結果を比較する
   - 移植と精度改善を同じ変更に混ぜない
   - 太陽の旧実装との数値差を確認する

5. Leafletを次の段階で地図コンポーネントへ移動する
   - 地図インスタンス
   - レイヤー
   - マーカー
   - ポップアップ
   - コンポーネント破棄時のcleanup

最初の実装単位としては、`main.js`をそのままVueコンポーネントへ変換するより、既存の太陽処理を壊さずにUI状態とLeaflet所有を分離するためのVue基盤を作るのが適切である。

## 未解決のリスク

- 太陽の時刻別位置計算と日の出・日の入り計算で近似式が異なる
- JST固定であり、一般的なタイムゾーンモデルではない
- 標高API失敗時にデフォルト値で処理を続けるため、結果の信頼性が見えにくい
- クリック時検索と期間検索に処理の重複がある
- 山の実行時登録は永続化されない
- グローバル変数とscript読み込み順に依存している
- 現在はVue/Viteのビルド・公開手順がない

このファイル作成では、`js/`、`css/`、`index.html`などの既存ソースコードは変更していない。
